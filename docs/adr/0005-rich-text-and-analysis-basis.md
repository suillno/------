# ADR 0005. 서식 저장 형식과 분석 기준 내용 판정

- 상태: 채택
- 날짜: 2026-10-20
- 관련: [plans/2026-10-20-rich-text.md](../plans/2026-10-20-rich-text.md)

## 배경

회의 본문·요약·결정사항을 서식(굵게·밑줄·글자색)이 적용된 화면에서 바로 편집한다. 서식만 바꿨을 때는 기존 분석 결과와 일정 후보를 유지하고, AI에 전달되는 실제 텍스트가 바뀌었을 때만 원문 변경으로 처리해야 하며, 이 구분을 서버도 같은 규칙으로 검사해야 한다.

## 결정

1. **편집기**: Tiptap 3(ProseMirror). 한글 조합 입력 처리, 스키마 기반 붙여넣기 정리, 표·목록·링크 확장을 갖춘다. 버전은 정확히 고정한다.
2. **저장 형식**: 기존 컬럼에 Markdown(GFM) + 허용 인라인 태그 2종(`<u>`, `style="color:#rrggbb"`만 가진 `<span>`). 기존 데이터는 변환하지 않는다. 편집기 문서(JSON) 별도 컬럼은 원본이 둘이 되어 동기화·충돌이 복잡해지므로 쓰지 않는다.
3. **분석 기준(basis)**: 제목·회의 일시·시간대·`analysisText(body)`의 정규 JSON. `meetings.analysis_revision_id`가 basis가 마지막으로 바뀐 revision을 가리키고, 원문 변경 판정은 `source_revision_id`와 이 값을 비교한다. 저장마다 version·revision 이력은 그대로 늘어난다.
4. **서버 검사 위치**: SQL은 Markdown을 해석할 수 없으므로 회의·편집본 저장을 Edge Function(`meeting-save`, `notes-save`)으로 옮긴다. 함수는 PC와 같은 변환 코드(`_shared/richtext.ts`, 같은 라이브러리 버전)로 basis·보이는 글자 수를 계산하고, 서비스 전용 RPC가 버전·소유·저장 길이·기준 revision을 다시 검사한다. 사용자 JWT의 직접 쓰기 RPC 실행 권한은 회수한다.

## 결과·위험

- 이전 버전 앱은 서버 변경 후 저장할 수 없다. 서버와 앱을 함께 갱신한다.
- 저장에 Edge Function 왕복이 추가된다(콜드 스타트 시 수백 ms~2초).
- 변환 규칙을 바꾸면 basis가 달라질 수 있으므로 규칙 버전(`analysis-text/v1`)을 basis에 넣고, 바꿀 때는 새 버전과 이행 방법을 함께 정한다.
- AI 입력이 Markdown에서 읽는 텍스트로 바뀌어 같은 본문도 재분석 결과가 조금 달라질 수 있다(기존 결과는 영향 없음).
