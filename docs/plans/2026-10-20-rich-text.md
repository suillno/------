# 서식 표시·편집 설계 (2026-10-20)

- 상태: 사용자 승인(2026-10-20). 결정 근거: [ADR 0005](../adr/0005-rich-text-and-analysis-basis.md)
- 범위: 회의 본문, AI 요약 원본, 요약·결정사항 편집본, 새 분석 결과 미리보기의 표시와 편집 (PC·안드로이드 공통)
- 유지 규칙: 수동 실행·승인, 중복 방지(`SingleFlight`·operation_id), 재분석이 편집본을 덮어쓰지 않음, 비밀값 규칙, 이미 적용한 마이그레이션 수정 금지

## 1. 표시

- 공통 읽기 화면 `RichView` 하나로 회의 본문·편집본·요약 탭 상세·새 결과 미리보기를 그린다. ‘원문 보기’는 없앤다.
- React 요소로만 그린다(HTML 문자열을 DOM에 넣지 않음). 링크는 이동하지 않는 텍스트 + 주소, 이미지는 대체 문구, 표는 가로 스크롤 상자.
- AI 출력(요약·결정사항 원본)은 **일반 텍스트**로 보여 준다(schema상 일반 문자열이며 `*`·`1.` 같은 기호를 서식으로 해석하지 않음). 편집본에 적용한 뒤부터 서식을 넣을 수 있다.
- 저장된 내용을 표시하려고 재분석하지 않는다.

## 2. 저장 형식: Markdown + 허용 인라인 태그 2종

| 서식 | 저장 |
|---|---|
| 굵게 | `**글자**` |
| 밑줄 | `<u>글자</u>` |
| 글자색 | `<span style="color:#rrggbb">글자</span>` (팔레트 색만) |
| 제목·목록·체크 목록·표·인용·링크·코드·구분선 | 기존 GFM Markdown |

- 위 두 태그 외 HTML은 읽을 때 태그를 버리고 글자만 남긴다(`<br>`은 줄바꿈). 기존 Markdown은 이 형식의 부분집합이므로 **일괄 변환하지 않는다**.
- 편집기가 다루지 못하는 요소(각주, HTML 블록, 이미지, 셀 안 블록 등)는 고칠 수 없는 블록으로 원래 Markdown을 그대로 보존한다.
- 편집기에서 실제로 바뀐 내용이 있을 때만 다시 직렬화해 저장한다. 열어 보기·취소는 원래 문자열을 그대로 둔다.
- 결정사항: 편집기에서는 글머리 목록 하나로 보이고, 목록 항목 1개 = 배열 요소 1개로 저장한다(서버 구조 그대로).

## 3. 글자색 팔레트

- 기본색 + 9색. ‘기본색’은 색 지정을 **해제**해 테마 기본 글자색을 따른다.
- 저장값은 팔레트의 `#rrggbb`만 허용(화면·서버 모두). 표시할 때는 같은 색을 밝은/어두운 화면용으로 대비를 맞춘 값으로 바꿔 보여 준다(저장값은 그대로라 기기 간 보존).
- 밝은(#ffffff)·어두운(#1b1b1f 계열) 배경 모두 WCAG 대비 4.5:1 이상을 테스트로 확인한다.

## 4. 편집기 (Tiptap 3.31.3, ProseMirror)

- 도구 모음 3개만: **B** 굵게, 밑줄 그은 ‘가’ 밑줄, 색상 박스.
- 선택 영역에 적용/해제. 선택 없이 설정하면 이후 입력에 적용(stored marks).
- 활성 표시: B·가 눌림 상태. 색상 박스: 선택 영역의 색(여러 색이면 대각선 반반 + ‘혼합’), 선택 없으면 이후 입력 색.
- 팔레트는 앱 안 팝업(시스템 색상창 미사용). 버튼은 포커스를 가져가지 않고(pointerdown 기본 동작 차단), 열 때 선택 위치를 저장했다가 적용 시 복원한다.
- 한글 조합 보호: 비제어 편집기(입력마다 내용 재주입 없음), 조합 중 도구 적용은 조합 종료 후 실행, 직렬화는 ‘저장’ 때만.
- 붙여넣기: 스키마에 있는 구조만 남김. 스크립트·iframe·이미지·이벤트 속성·`javascript:`·팔레트 밖 색 제거. 편집기 안 링크는 열리지 않음.
- 휴대폰: 도구 모음은 편집 영역 상단에 고정, 키보드가 올라오면 `visualViewport` 기준으로 키보드 위에 둔다. 버튼 44px 이상. 표는 가로 스크롤.

## 5. 분석 기준 내용과 원문 변경 판정

### 5.1 분석 입력 텍스트
- 변환 함수 `analysisText(markdown)`(규칙 버전 `analysis-text/v1`)가 서식 기호를 뺀 읽는 텍스트를 만든다.
  - 제목 → 한 줄, 목록 → `- `/`1. `/`[x] ` 접두, 표 → 행마다 `셀 | 셀`, 링크 → `글자 (주소)`, 인용 → `> `, 코드 → 원문 그대로, 굵게·밑줄·색 → 글자만.
  - 링크 주소·표 셀·목록 구분·줄바꿈은 남긴다(의미 있는 내용 보존).
- **분석 기준(basis)** = `{ v: "analysis-text/v1", title, meeting_at(UTC ISO), time_zone, text: analysisText(body) }`의 정규 JSON. 분석 추가 요청사항은 작업(job)마다 고정되며 작업 입력 해시(config_hash)에 이미 포함된다.
- 같은 변환 코드 파일(`supabase/functions/_shared/richtext.ts`)을 서버(Edge Function, Deno)와 PC 앱(TS)이 함께 쓰고, 같은 고정 자료로 양쪽 테스트를 돌린다. PC는 CLI에 `body` 대신 이 텍스트를 넘긴다.

### 5.2 데이터
- `meetings.analysis_revision_id`(신규): 분석 기준 내용이 마지막으로 바뀐 revision. 기존 행은 `revision_id`로 채운다(기존 결과·후보의 유효성 그대로).
- 모든 저장은 `version`을 올리고 새 `revision_id`(이력)를 만든다. 분석 기준이 같으면 `analysis_revision_id`는 그대로, 다르면 새 revision으로 바꾼다.
- 작업·결과·후보의 `source_revision_id`는 분석 기준 revision을 가리키며, 그 revision 스냅샷(분석 당시 원문)은 보존된다.
- 원문 변경(stale) 판정은 전부 `source_revision_id <> meetings.analysis_revision_id`로 바꾼다(서버: submit_result, analysis_state, summaries, candidate_approve, analysis_request, claim / 화면: analysisView, jobBadge, 회의 상세 안내).

### 5.3 서버 검사

> 구현 시 조정(2026-10-20): 사용자 JWT 경로 `meeting_patch`·`meeting_notes_patch`는 회수하지 않고 **기존 동작(항상 원문 변경·저장 4000/1000자)** 으로 유지했다. ‘결과 유지’·‘서식 포함 12000자’는 서버 판정 경로(서비스 전용 RPC)만 할 수 있어 우회가 불가능하고, 이전 버전 앱도 지금처럼 저장할 수 있다. 회의 생성은 판정할 것이 없어 기존 `meeting_create`를 쓴다. 글자색 팔레트 검사는 SQL에서도 한다(모든 경로).

- DB(SQL)는 Markdown을 해석할 수 없으므로 저장은 Edge Function을 거친다.
  - `meeting-save`: 생성·수정. 사용자 JWT 확인 → 현재 분석 기준 revision의 스냅샷과 새 값의 basis를 같은 코드로 계산·비교 → 서비스 전용 RPC `svc_meeting_save(p_user_id, …, p_expected_analysis_revision_id, p_analysis_changed)`.
  - `notes-save`: 요약·결정사항 편집본. 보이는 글자 수·저장 길이·팔레트 색 검사 → `svc_meeting_notes_patch(p_user_id, …, p_summary_visible_len, p_decision_visible_lens)`.
- RPC는 버전·소유·저장 길이·`p_expected_analysis_revision_id`(그 사이 다른 저장이 없었는지)를 다시 검사한다. 사용자 JWT로는 `meeting_create`·`meeting_patch`·`meeting_notes_patch`를 더 이상 실행할 수 없다(서버 검사 우회 방지).
- **배포 순서 주의**: 서버를 바꾸면 이전 버전 앱(설치본·APK)은 저장할 수 없으므로 서버 배포와 두 앱 업데이트를 함께 한다.

### 5.4 유지되는 것 (서식만 바꾼 경우)
- 대기·실행 중 분석: 그대로 진행, 결과는 stale 아님.
- 완료 결과·편집본: 그대로.
- 미등록 후보: 승인 가능 상태 유지(같은 payload_hash).
- 이미 등록된 Google 일정: 수정·재등록하지 않음(서식 저장은 캘린더 경로를 호출하지 않음).

## 6. 글자 수 기준

- **보이는 글자** = `visibleText`(analysisText와 같은 규칙에서 줄 접두 기호를 뺀 텍스트)의 유니코드 코드 포인트 수. 화면(`[...s].length`)·Edge Function·SQL(`char_length`)이 같은 값을 쓴다. 줄바꿈은 1자.

| 항목 | 보이는 글자 | 저장(서식 포함) |
|---|---|---|
| 요약 편집본 | 4,000 | 12,000 (2026-10-20 확정) |
| 결정사항 항목 | 1,000 | 3,000 (2026-10-20 확정) |
| 결정사항 개수 | 50 | 50 |
| 회의 본문 | — | 1,000,000 bytes (기존) |
| AI 출력 schema 요약 | 4,000 (변경 없음) | — |

- 측정(보이는 글자 약 4,000자): 서식 없음 3,976 / 문장 1/3 굵게+밑줄+색 6,184 / 모든 문장 색 8,946 / **모든 문장 굵게+밑줄+색 10,508** / 단어마다 굵게+색 26,266 / 단어마다 굵게+밑줄+색 30,263. 모든 문장에 서식 세 가지를 넣어도 들어가는 12,000자로 정했다. 결정 항목은 1,000자 전체에 세 가지를 넣어도 1,040자라 3,000자로 충분하다.
- 서식 경계 옆 글자는 직렬화 라이브러리가 문자 참조(`&#x…;`)로 적는다(서식이 정확히 다시 읽히도록). 화면·AI 텍스트에는 원래 글자로 보인다.
- 초과하면 자르지 않고 저장 전에 화면에 ‘보이는 글자 n/4000’ 또는 ‘서식이 너무 많습니다’로 안내하고 저장 버튼을 막는다. 서버도 같은 값으로 거절한다(400 VALIDATION_FAILED, 입력 보존).

## 7. 편집 보호·충돌

- 휴대폰에서도 PC와 같이 요약·결정사항 편집(같은 도구 모음). AI 원본은 읽기 전용.
- 편집 중에는 자동 갱신(포커스·화면 복귀·분석 완료 이벤트)과 재분석 결과가 편집 내용을 바꾸지 않는다. 바뀐 서버 내용은 ‘최신 내용이 있습니다’로만 알린다.
- 저장은 base version으로 검사한다. 409면 입력을 보존하고 **내 편집 / 서버 최신 내용을 나란히** 보여 준다. 선택지: ‘최신 내용 불러오기’(내 편집 버림, 확인 후) · ‘내 편집으로 다시 저장’(최신 version 기준으로 다시 검사). 자동 병합은 하지 않는다.
- 저장하지 않은 편집이 있으면 탭 이동·화면 이동·안드로이드 뒤로가기·창 닫기 전에 확인한다. 앱 강제 종료는 확인할 수 없다(한계).

## 9. 순서

1. 공유 변환 코드 + 고정 자료 테스트(Node·Deno)
2. 마이그레이션 + pgTAP
3. Edge Function 2개 + 테스트
4. client-core(API·판정·PC 입력 변환)
5. 편집기·표시 화면(PC·휴대폰), 충돌·이탈 처리
6. 저장 한도 측정 → 값 확정
7. 로컬 통합 테스트, 빌드
8. 클라우드 적용(사용자 확인) + 설치본·APK 동시 갱신
